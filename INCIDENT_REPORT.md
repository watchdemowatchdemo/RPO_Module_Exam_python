# Отчет об устранении инцидентов (Incident Report)

## Инцидент №1: Отсутствие файла .gitignore

**СИМПТОМ:**
В системе контроля версий Git индексируются локальные конфигурационные файлы проекта (включая секреты `.env`), кэш компиляции и временные артефакты среды разработки. Это создает критический риск публикации приватных ключей доступа в общий репозиторий и засоряет историю коммитов избыточными системными данными.

**ПРИЧИНА:**
В корневом каталоге проекта отсутствовал конфигурационный файл `.gitignore`. Из-за этого механизм отслеживания Git автоматически захватывал любые новые файлы и изменения, созданные локально на машине разработчика.

**РЕШЕНИЕ:**
1. В корневом каталоге проекта инициализирован и настроен файл `.gitignore`.
2. Прописаны правила исключения для переменных окружения, системных папок IDE и кэша.
3. Из индекса Git принудительно удалены ранее отслеживаемые служебные файлы с помощью команды `git rm --cached`.

**КОММИТ:**
`add gitignore` `d523885d7e4e4ceb384292cea92513d71a9c6462`

## Инцидент №2: Отсутствие зависимости pydantic-settings

**СИМПТОМ:**
При попытке развернуть бэкенд-сервер через интерфейс uvicorn процесс аварийно завершается с ошибкой ядра `ModuleNotFoundError: No module named 'pydantic_settings'`. Сбой происходит на этапе инициализации приложения при чтении файла конфигурации `core/config.py`.

**ПРИЧИНА:**
В конфигурационном файле пакетов `requirements.txt` не была задекларирована обязательная библиотека `pydantic-settings` и сопутствующий пакет `pydantic`. Из-за этого при сборке виртуального окружения модуль для валидации параметров `BaseSettings` не загружался.

**РЕШЕНИЕ:**
1. В файл зависимостей `backend/requirements.txt` добавлены две пропущенные строки: `pydantic-settings==2.14.1` и `pydantic>=2.0`.
2. Выполнена повторная синхронизация библиотек виртуального окружения через команду `pip install -r requirements.txt`.

**КОММИТ:**
`fix(deps): add pydantic-settings and pydantic to requirements` `99947e98c18344cf0506005bfe544584ce6fe10e`

## Инцидент №3: Некорректный путь хранения логов

**СИМПТОМ:**
Локальный старт бэкенд-сервиса прерывается системным отказом файловой системы: `PermissionError: [Errno 13] Permission denied: '/var/log/nexus_monitor_production/'`. Проект не может запустить обработчики событий.

**ПРИЧИНА:**
В модуле конфигурации журналов `core/logging_config.py` переменная `LOG_DIR` содержала жестко прописанный абсолютный путь для production-среды (`/var/log/...`). При тестировании на локальной машине пользователя права на запись в эту системную директорию отсутствуют.

**РЕШЕНИЕ:**
1. Отредактирован файл конфигурации логгера `backend/core/logging_config.py`.
2. Абсолютный путь изменен на относительный локальный путь `"log/nexus_monitor_production"`, доступный для текущего процесса.

**КОММИТ:**
`fix(logs): fix writable directory path and switch level to debug` `c4ceed280cc99e47a0c9162ab9dc180b446092d1`

## Инцидент №4: Некорректный порт PostgreSQL

**СИМПТОМ:**
Приложение падает на этапе инициализации пула соединений с БД, возвращая ошибку драйвера `psycopg2.OperationalError: connection to server at "localhost", port 5433 failed: Connection refused`. Связь с данными отсутствует.

**ПРИЧИНА:**
В локальных параметрах подключения к СУБД в файле конфигурации окружения бэкенда (`backend/.env`) был ошибочно указан порт `5433`. Фактический же сервер базы данных PostgreSQL был развернут и принимал запросы на стандартном дефолтном порту `5432`.

**РЕШЕНИЕ:**
1. Внесены изменения в конфигурационный файл `backend/.env`.
2. Значение целевого сетевого порта `DB_PORT` исправлено с `5433` на корректный рабочий порт `5432`.

**КОММИТ:**
НЕ КОММИТЯТ

## Инцидент №5: Некорректный URL API во frontend (.env Vite)

**СИМПТОМ:**
Интерфейс пользователя (фронтенд) отображает пустые страницы и не загружает динамические данные от сервера. В консоли браузера фиксируется сетевое исключение `TypeError: Failed to fetch` при выполнении запросов в компоненте `App.jsx`.

**ПРИЧИНА:**
В конфигурационном файле `.env` клиентской части переменная `VITE_API_URL` содержала ошибочный адрес эндпоинта `http://localhost:8001/api`. При этом бэкенд-сервер обрабатывал входящие запросы на порту `8000`.

**РЕШЕНИЕ:**
1. Внутри каталога фронтенда отредактирован файл локального окружения `.env`.
2. Значение адреса API `VITE_API_URL` изменено на корректный порт бэкенда `http://localhost:8000/api`.
3. Сервер сборщика Vite перезапущен для обновления кэшированных переменных.

**КОММИТ:**
ЭТА ХАМИТЫТ НИЛЗЯ

## Инцидент №6: Некорректный уровень логирования

**СИМПТОМ:**
Система логирования работает в усеченном режиме: в консоль разработчика и файлы записываются только события с приоритетом `INFO`. Детальные отладочные трассировки (`DEBUG`) и системные предупреждения (`WARNING`) полностью отсутствуют, что усложняет поиск багов.

**ПРИЧИНА:**
В коде бэкенда (`core/logging_config.py`) при инициализации базового логгера через метод `logging.basicConfig` был жестко зафиксирован пороговый уровень `level=logging.INFO`, который автоматически отсекал любые сообщения с меньшим приоритетом.

**РЕШЕНИЕ:**
1. Внесены изменения в конфигурационный скрипт логирования бэкенда `backend/core/logging_config.py`.
2. Глобальный минимальный уровень фильтрации логов понижен со значения `logging.INFO` до `level=logging.DEBUG`, а также добавлен обработчик `logging.StreamHandler()`.

**КОММИТ:**
`fix(logs): fix writable directory path and switch level to debug` `c4ceed280cc99e47a0c9162ab9dc180b446092d1`
